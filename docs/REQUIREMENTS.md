# 채록 폰 전용판 요구사항 (단일 원본)

> 기능 요구사항 + 수용 기준의 단일 원본. **요구사항이 바뀌면 대화로 합의만 하지 말고 이 파일을 즉시 갱신.**
> 완료 판정은 항상 이 문서를 기준으로 한다(에이전트를 쓰든 직접 대조하든).
> **새 F-번호는 CLAUDE.md의 '요구사항 ID 대장'에서 받아간다. 번호 재사용 금지.**

## 시스템 목표
- 폰에서 본 글·링크·사진·문서·녹음을 손동작 한두 번으로 모으고, AI가 분류·정리해 주고, 모은 것을 놓고 AI와 대화하는 개인 앱.
  매일 계획 달력과 외울 문장 보관함이 함께 있다.
- 기존 「채록」은 원본을 Google Drive에 두고 PC 프로그램과 짝을 이뤘다. 이 판은 **폰 하나로만** 돈다 —
  설치하고 AI 키만 넣으면 바로 쓰고, 친구에게 APK로 나눠 준다(사용자 결정 2026-11-19).

## 사용자/권한
- 역할은 하나다: 폰 주인. 계정·로그인이 없다.
- 네 자리 비밀번호는 **API 키를 넣거나 바꿀 때만** 묻는다. 설정 화면 자체는 그냥 들어간다.
- Google 계정·로그인을 쓰지 않는다.

## 화면 방향
1. **UI 형태**: 안드로이드 앱(Flutter).
2. **기준 기기·해상도**: 갤럭시 세로 화면. 가로·태블릿은 따로 맞추지 않는다.
3. **룩앤필의 기준**: **기존 「채록」 앱과 같게 만든다** — 화면 구성·이동·문구·색·모양. 사용자가 실기기에서 확인한 모양이다.
   - 테마: 기존 `app/lib/theme.dart`(디자인 B 세이지 라운드, 라이트·다크) + `app/assets/fonts/`(GothicA1).
   - 화면 이동: 기존 `app_menu.dart` — 어느 화면에서든 앱바 오른쪽 `⋯` 메뉴(계획·붙여넣기·목록·대화·외울 문장·설정).
   - 첫 화면은 계획 달력.
   - 아이콘: 기존과 같은 펜촉 그림에 **색만 밝게**(사용자 결정 2026-11-19, 목업에서 '다' 선택) — 밝은 파랑 `#378ADD` 바탕 + 연한 금색 `#FAC775` 펜촉 + 짙은 파랑 `#0C447C` 선.
     기존판은 남색 `#042C53` 바탕이라 두 앱을 함께 깐 폰에서 색으로 구분된다(앱 이름은 둘 다 '채록').
4. **피할 모양**: 기존판에 없는 모양을 새로 들이지 않는다. 새로 생기는 설정 칸(글자 수집기 주소)은 기존 설정 화면의 절 모양을 따른다.
5. **다크모드 / 접근성 / 언어**: 다크모드·글자 크기는 시스템 설정을 따른다. 한국어만.
6. **첫 화면 확정 방식**: 기존 앱이 기준이라 목업을 새로 그리지 않는다. 애매하면 기존 앱의 동작을 본다(사용자 폰에 깔려 있다).
   새로 생기는 화면만 구현 전에 목업으로 "이대로"를 받는다.

## 기능 요구사항

### 번호와 수용 기준을 다루는 법
- **F-001~F-034는 기존판의 번호를 그대로 잇는다.** 기존 수용 기준의 원본은 기존 프로젝트
  `docs/REQUIREMENTS.md` + `docs/requirements/*.md`(수집·목록_분류·대화·계획·앱_설정·외울_문장)이다.
- **기능을 옮기는 Phase를 시작할 때, 그 기능의 수용 기준을 이 저장소 `docs/requirements/<도메인>.md`로 옮겨 적는다**
  (Drive → 폰 저장으로 고치고, 아래 '옮길 때 바로잡을 것'을 반영해서). 옮겨 적기 전에는 그 기능을 구현하지 않는다.
  옮겨 적은 뒤에는 이 저장소의 문서가 단일 원본이고 기존 문서는 더 보지 않는다.
- 아래 표의 '새 판에서 달라지는 것'은 옮겨 적을 때 지켜야 하는 결정이다.

### 목록·붙여넣기 숨김 + 앱 이름 '계획실천' (2026-11-19 사용자 결정)
- 앱 이름(런처·작업 전환 화면)을 '채록'에서 **'계획실천'**으로 바꿨다. 패키지 이름은 그대로(`com.brad0329.chaerok.phone`).
- **붙여넣기 화면(F-003·F-007 녹음 입구 포함)과 목록(F-010·F-018·F-029)을 화면에서 완전히 숨겼다** — `main.dart`의 조립만 주석(`[숨김]`)으로 막았고
  소스와 테스트는 그대로 있다. 맨 밑 화면은 계획 달력, ⋯ 메뉴는 계획·설정 둘. 아래 표의 '완료'는 기능이 만들어져 있다는 뜻이고 지금 앱에서는 안 보인다.
- **공유 메뉴의 '채록'(F-002)은 숨기지 않았다(사용자 확인 대기)** — 공유로 받은 것은 폰에 저장되지만 목록이 숨겨져 있어 볼 곳이 없다.
- 아이콘은 사용자가 예시 셋 중에서 고르는 중.

### 새 기능

### F-035: 폰 안 저장
- **설명**: 수집물 원본·사이드카·AI 결과·사용자 수정·자막을 앱 전용 폴더에 파일로 둔다. 형식은 `docs/SCHEMA.md`.
  기존판의 Drive 인터페이스 네 개(쓰기·읽기·덧붙이기·지우기) 자리에 폰 폴더 구현을 끼운다.
- **수용 기준**:
  - [x] 글 한 건을 저장하면 `records/YYYY-MM/`에 `<base>.txt`와 `<base>.meta.json` 두 파일이 생기고, 사이드카의 `md5`·`size`가 원본 파일과 일치한다.
  - [x] 사이드카는 14항목을 모두 갖고(없는 값은 `null`), `device`는 `phone`, `schema_version`은 1이다.
  - [x] 저장 직후 목록 읽기가 그 건을 1건으로 돌려준다(네트워크 없이).
  - [x] 원본만 있고 사이드카가 없는 파일은 목록에 나오지 않고 "읽지 못함" 건수에 1로 잡힌다.
  - [x] 같은 초에 두 건을 저장해도 base가 겹치지 않고 두 건 모두 남는다.
  - [x] 저장 중 실패하면(쓰기 오류를 일으켜) 반쪽 파일이 수집물로 보이지 않고, 실패가 로그에 남고 화면에 실패로 표시된다.
  - [x] 기존판 형식의 파일(사이드카 `input: pc_text`, `device: pc`)을 폴더에 넣으면 목록이 그대로 읽는다.
  - [x] 한 건을 지우면 그 건의 `<base>.` 파일이 0개가 되고 다른 건의 파일 수는 변하지 않는다.
  - [x] 파일을 쓰는 코드 지점이 `file_writers_test` 등록부와 정확히 일치한다(새 지점을 넣고 등록을 빼먹으면 실패).
  - [x] 저장 위치 이름이 `app_paths_test`의 고정값과 일치한다.
- **엣지케이스**: 폰 용량 부족 → 저장 실패로 표시하고 이미 쓴 반쪽 파일을 지운다 / 공유 엔진·분류 작업·화면이 동시에 쓰는 경우 → 서로 다른 파일만 쓰게 하고 등록부에 주체를 적는다.
- **상태**: 완료(2026-11-19) — 자동 테스트 + 사용자 실기기 확인 + spec-checker 대조·qa-tester 합격(`phone_store_test`·`record_delete_test`·`file_writers_test`·`app_paths_test`)
- **Phase 003에서 정한 것**(2026-11-19): 같은 이름의 파일이 이미 있으면 쓰기를 거부한다(덮어쓰지 않음) / 파일 이름에 경로 조각이 섞이면 저장하지 않는다 /
  "화면에 실패로 표시" = 화면 저장은 상태 줄, 공유 엔진은 알림(F-002) / 저장 중 앱이 죽어 남은 사이드카 없는 원본은 "읽지 못함"으로 두고 치우는 기능은 보류(사용자 결정, plan.md 보류 항목)

## 비기능 요구사항
1. **인증 방식**: 없음. 서버·계정이 없는 폰 앱이다. 네 자리 비밀번호는 API 키 넣기·바꾸기에만 건다.
   Google 로그인·OAuth는 없다.
2. **공개 범위**: 공개 엔드포인트·서버 없음. 밖에서 들어오는 입력은 안드로이드 공유 인텐트(다른 앱이 넘기는 글·파일) 하나다 —
   파일 경로 정규화와 크기 상한을 건다.
   밖으로 나가는 통신: Anthropic·Google Gemini(사용자가 넣은 키로), youtube.com(자막·플레이어), 사용자가 설정에 넣은 글자 수집기 서버.
3. **성능·기타**: 수집 입구마다 손동작 2초 이내(기존판과 같음). `allowBackup=false` 유지. 로그에 본문·키·이메일 0번.
   상한값(공유 100MB, 문서 30MB, 대화 30건·20만 자, 분류 한 번에 50건 등)은 기존판 값을 그대로 가져오고 `limits_test`로 건다
   (공유 100MB만 예외 — Kotlin `ShareActivity`의 상수라 Dart 테스트가 닿지 않는다. 경계값 자동 테스트 없음).

## 미결 질문
- **첫 실행에서 비밀번호를 언제 정하나**: Drive 단계를 빼면 "AI 키 단계만" 남는데, 키를 넣으려면 비밀번호가 있어야 한다.
  가정: 키를 처음 넣을 때 비밀번호를 먼저 정하게 한다(기존판의 '비밀번호 → 키' 순서를 유지). Phase 005(설정(AI)·첫 실행) 전에 확인.
- **친구용 고지**: 수집물이 자동으로 AI 제공자에게 전송된다는 것을 첫 실행 화면에 한 줄로 알릴지. 가정: 알린다(키 넣는 화면에 한 줄).
- **기본 비밀번호 복구**("3번 틀리면 소스의 기본 비밀번호")는 1인 전제였다 — 친구에게 주는 앱에서 어떻게 할지. Phase 005(설정(AI)·첫 실행) 전에 묻는다.
- **유튜브 자막(F-014)** 은 비공식 경로라 예고 없이 끊길 수 있다 — 친구에게 알릴지는 배포 준비 Phase에서.
- **폰 용량 표시·정리 기능**이 필요한가 — 원본이 전부 폰에 쌓인다. 가정: 이번 범위에 넣지 않는다.
- 기존판 보류 항목(STT, PDF 읽기, RAG 대화, 핵심 정리 서식 편집)은 새 판 대장에 옮기지 않았다 — 필요해지면 새 번호로.
