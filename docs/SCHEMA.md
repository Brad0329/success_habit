# 채록 폰 전용판 데이터 모델 — 스키마 변경 결정 기록

> **AI는 임의로 항목 추가/변경, 마이그레이션 수정을 하지 않는다.**
> 스키마 변경 절차: ① 변경안을 이 문서 '변경 이력'에 먼저 기록 → ② 사용자 확인 → ③ 코드 반영
> → ④ **구버전 저장본을 실제로 읽어 마이그레이션 실측 + 되돌리기 경로(백업·롤백) 확인 + 사용자 실테스트**
> 후 배포 (일반 트랙 검증 갈래, CLAUDE.md '검증 강도'). 새 코드로 만든 빈 저장소는 통과하고 옛 저장소만 깨진다.
> 이 문서는 "결정과 이유"를, 코드는 "현재 상태"를 담당한다. 항목 목록을 손으로 이중 관리하지 않는다 —
> 아래 항목 이름은 기존판에서 물려받은 것을 적어 둔 출발점이고, 코드가 생기면 코드가 정답이다.

> **상태: 초안(2026-11-19) — 사용자 확인 대기.** 확정 전에는 저장 코드를 쓰지 않는다.

## 설계 원칙
1. **저장소는 파일 나무 하나다.** 데이터베이스를 쓰지 않는다. 앱 전용 폴더(`filesDir`) 아래에 파일로 둔다.
2. **백업·내보내기·기기 옮기기 수단이 없다**(사용자 결정 2026-11-19 — Drive 백업·복원·zip을 모두 뺐다).
   앱을 지우거나 폰을 잃으면 데이터가 사라진다. Google Drive·OAuth를 쓰지 않는다.
3. **수집물의 키는 base(`YYYYMMDD-HHMMSS_<ID 앞 8자>`)다.** Drive 파일 ID를 어떤 영속 데이터의 키로도 쓰지 않는다
   (기존판은 대화 기록·목록 캐시·이미지 보관·분류 상태에 Drive ID가 박혀 있었다).
4. **수집물 파일은 한 번 쓰면 고치지 않는다(추가만).** AI 결과·사용자 수정은 새 파일을 덧붙이고, 읽을 때 가장 늦은 것을 고른다.
5. **사용자 데이터와 산출물을 다른 폴더에 둔다.** 산출물(캐시·상태)은 지워도 사용자 데이터에서 다시 만들 수 있어야 한다.
6. **모든 쓰기는 임시 파일에 쓰고 이름 바꾸기**(기존 `atomic_file.dart`). 쓰는 곳은 `file_writers_test` 등록부로 고정한다.
## 핵심 엔티티와 관계
- **수집물(record)** 1건 = 원본 파일 1 + 사이드카 1 + 덧붙임 파일 0..N(ai · user · transcript). 모두 같은 base로 묶인다.
- **사진 묶음** = 수집물 N건이 같은 `group_id`를 가진다. AI 결과는 대표 장 1건에만 붙는다.
- **대화(chat)** 1건 = 파일 1개. 수집물을 base로 가리킨다(맥락·항목 대화).
- **외울 문장** = 파일 1개 안의 목록. 원본을 수집물 base 또는 대화 id로 가리킨다.
- **계획·하루 평가** = 파일 2개. 다른 것과 관계 없음.

## 도메인별 설계 결정

### 폰 안의 폴더 나무
```
filesDir/
  records/YYYY-MM/                 ← 사용자 데이터. 수집 시각 기준 월별
    <base>.<확장자>                  원본 (텍스트·URL은 .txt, 그 외는 원래 확장자)
    <base>.meta.json                사이드카
    <base>.ai-<YYYYMMDD-HHMMSS>.json        AI 분류·정리 결과
    <base>.user-<YYYYMMDD-HHMMSS>.json      사용자 수정
    <base>.transcript-<YYYYMMDD-HHMMSS>.json  유튜브 자막
  chat/<id>.json                   ← 사용자 데이터. 대화 기록
  plans/plans.json, reviews.json   ← 사용자 데이터. 계획·하루 평가
  memorize/memorize.json           ← 사용자 데이터. 외울 문장
  settings/                        ← 사용자 설정 (API 키·비밀번호·카테고리 등)
  collection_cache/, classify_state.json, classify_requests/, changed.txt, sent_clip.md5, …  ← 산출물
```
- **결정**: 수집물은 `records/YYYY-MM/`에 기존판 Drive와 같은 파일 이름으로 둔다.
- **이유**: 기존 코드의 짝짓기(`listRecords`)·덧붙임 파일 선택(`ai_result.dart`)·지우기(`<base>.` 접두 전부)가
  이름 규칙 위에서 돈다 — 저장소 구현만 갈아 끼우면 로직이 그대로 돈다(2026-11-19 코드 조사).
- **버린 대안**: ① sqlite — 원본이 어차피 파일이고, 기존 코드가 파일 이름 규칙 위에서 돌아 옮길 것이 늘어난다.
  ② 공유 저장소(문서/채록) — 저장소 권한 제약으로 구현이 크게 복잡해진다(사용자 결정 2026-11-19: 앱 전용 폴더).
  ③ 건마다 폴더 하나 — 기존 이름 규칙 코드를 버려야 한다.

### 수집물 쓰기 순서와 미완성 판정
- **결정**: 원본을 먼저 쓰고 사이드카를 나중에 쓴다. **사이드카가 있어야 수집물이다.**
  사이드카 없는 원본은 목록에 내지 않고 "읽지 못함 N건"으로 센다(기존판 동작 유지).
- **이유**: 쓰는 주체가 셋(화면·공유 엔진·분류 작업)이고 중간에 죽을 수 있다. 사이드카를 완료 표시로 쓰면 별도 장부가 필요 없다.
- 기존판의 임시 보관함(`pending/`)·업로드·MD5 대조는 없어진다 — 폰에 쓰는 것이 곧 저장이다.

### 사이드카 (`schema_version` 1 — 기존판과 같은 번호를 잇는다)
- **결정**: 기존판 14항목을 그대로 둔다: `schema_version`, `id`, `collected_at`, `input`, `kind`, `source`, `device`,
  `original_name`, `mime`, `size`, `md5`, `caption`, `group_id`, `group_size`. 없는 값은 `null`, 항목은 빠지지 않는다.
  - 새 앱이 쓰는 `input`은 `share`·`paste`·`voice`뿐이고 `device`는 항상 `phone`이다.
  - 읽을 때는 기존판 값(`pc_text`·`pc_capture`·`pc_file`, `device: pc`)도 받아들인다.
- **이유**: 기존 코드(`record.dart`)와 그 테스트가 14항목을 전제로 한다. 항목을 빼면 옮기는 코드를 고쳐야 하고, 남겨 두는 비용은 없다.
- AI 결과·사용자 수정·자막 파일의 형식도 기존판과 같다(`ai_schema_version` 1 · `user_schema_version` 1 · `transcript_schema_version` 1).
  읽는 규칙도 같다: 종류마다 이름이 가장 늦은 파일, 항목별로 user가 ai보다 우선.

### 수집물을 가리키는 방법 (Drive ID를 대체)
- **결정**: 수집물 = base, 그 안의 파일 = 파일 이름(나무 안 상대 경로 `records/YYYY-MM/<이름>`).
  - 대화 기록의 맥락 블록(`ContextBlock.fileId`) → 상대 경로.
  - 목록 캐시의 `original_id`·`meta_id`·`folder_id` → 없앤다(경로는 base에서 나온다).
  - 이미지 보관(`PhotoCache`) → 없앤다(원본이 폰에 있다).
  - 분류 상태의 미리 받은 ID(`ClassifyState.ids`) → 없앤다. 결과 파일 이름의 시각이 겹치지 않게만 한다.
- **이유**: base와 사이드카 `id`는 폰에서 만들어지고 변하지 않는다. 대화·외울 문장·분류 상태가 이미 base를 쓴다.

### 폰에만 있던 저장 (형식은 기존판 그대로)
- `chat/<id>.json`(`version` 1), `plans/plans.json`·`plans/reviews.json`, `memorize/memorize.json`, `settings/*`.
- **결정**: 형식을 바꾸지 않는다(`memorize.json`에 `version` 키가 없는 것도 그대로 둔다).
- **이유**: 화면·로직을 그대로 옮기기 위해서다.
- `settings/`의 API 키 파일·비밀번호 파일은 평문이고 앱 전용 폴더 + `allowBackup=false`로 지킨다(기존판과 같음).
