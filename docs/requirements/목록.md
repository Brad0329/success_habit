### F-010: 수집물 목록 · 검색 · 항목 보기
- **설명**: `records/` 아래 모든 달 폴더를 읽어 날짜별 목록으로 보이고, 글자로 찾고, 한 건을 눌러 전체를 본다. 네트워크를 쓰지 않는다.
  Phase 003에는 AI 분류가 없다 — 카테고리 칩·요약·핵심 정리·유튜브·문서 본문·'이것으로 대화하기'는 Phase 005~006에서 붙는다.
- **결정**(2026-11-19 구현 가정 — 사용자에게 보고): **디스크 캐시를 두지 않는다.** 기존판 캐시는 Drive 내려받기를 줄이려던 것이고 원본이 폰에 있다.
  마지막으로 읽은 목록을 메모리에 들고 두 번째부터는 새 수집물만 읽는다(앱을 새로 켜면 전부 다시 읽는다 — 실기기 속도는 재지 않았다).
  Phase 005에서 문서 글 뽑기가 들어오면 그 결과의 캐시를 다시 본다.
- **수용 기준**(테스트: `collection_list_test`·`collection_screen_test`):
  - [x] 목록: `2026-10` 2건 + `2026-11` 3건 → 5건, 시각 내림차순, 상태 줄 "전체 5건 · HH:MM 갱신"
  - [x] 모든 달: `YYYY-MM` 이름의 폴더는 다 읽고 다른 이름의 폴더는 읽지 않는다
  - [x] 읽지 못함: 사이드카 없는 원본 + 원본 없는 사이드카 + 깨진 사이드카(JSON 아님·문자열 항목 타입 틀림) → 목록에서 빠지고 "읽지 못함 N건", 로그에 그 base가 남는다
  - [x] 덧붙임 파일: `<base>.ai-….json`·`<base>.user-….json`·`<base>.transcript-….json`·모르는 꼬리(`<base>.foo.bar`)·쓰다 만 `.tmp`가 있어도 그 수집물은 1건이고 "읽지 못함"에 세지 않는다
  - [x] 결과 파일이 있으면 SCHEMA 규칙대로 읽는다 — 제목은 종류마다 이름이 가장 늦은 파일, user가 ai보다 우선 / 결과 파일만 새로 생기면 원본·사이드카는 다시 읽지 않는다
  - [x] 기존판 형식(`input`=`pc_text`·`device`=`pc`)의 건은 "PC"로, 폰 건은 "폰"으로 나온다
  - [x] 상한 없음: 1,500건 → 목록 1,500건·"전체 1500건", 검색 결과도 자르지 않는다
  - [x] 검색 대상: "니체"가 원문에만·메모에만·파일 이름에만·출처에만 있는 4건 → 검색 결과 3건(출처 건 제외)
  - [x] 검색 규칙: 두 단어 모두 든 것만(AND) / 대소문자 무시 / 공백만이면 전체 / 0건이면 상태 줄 "검색 결과 0건 / 전체 M건"
  - [x] 새로 고침이 겹쳐도 폴더 읽기는 한 번 / 두 번째 새로 고침은 새 수집물만 읽는다
  - [x] 일부 읽기 실패: 5건 중 1건이 입출력 오류 → 4건 + "1건 못 읽음", 다음 새로 고침에 그 1건을 다시 읽는다
  - [x] 항목 보기 — 텍스트: '복사'를 누르면 클립보드 = 원문 전체 / 녹음 항목에는 '복사'가 없다
  - [x] 항목 보기 — 링크: http(s) 주소면 '브라우저로 열기'를 누를 때 그 주소로 열기 채널 호출 1회 / 일반 글에는 없다
  - [x] 항목 보기 — 이미지: 폰 파일을 1번 읽는다 / 못 읽으면 "이미지를 못 읽음" + '다시 시도'
  - [x] 항목 보기 — 녹음: '재생'을 누르면 폰 기본 앱 열기 채널 호출 1회(MIME = 사이드카 `mime`) / 그 외 파일: "파일 이름 · 크기"만
  - [x] 목록·항목 보기에 "Drive"·"이것으로 대화하기"·"보내지 못한 것" 글자가 나오지 않는다
  - [x] 로그에 수집물 본문·메모가 0번 나온다(건수·base만) / 규칙에 안 맞는 파일 이름도 로그에 남기지 않는다(글자 수만)
  - (사용자 실테스트) 목록(검색칸·상태 줄·날짜 머리줄·카드 줄·새로 고침·당겨서 새로 고침)·항목 보기(텍스트·링크·이미지 크게·녹음 재생·파일)가 기존판과 같은 모양 / 다크 모드 /
    "'<검색어>' 결과 없음"·"아직 수집물이 없습니다" 문구
- **Phase 003에서 안 보이는 것**: 유튜브 링크·docx 등은 일반 링크·일반 파일로 보인다(Phase 005) / 본문 글의 '외울 문장' 고르기 메뉴(Phase 007)
- **상태**: 완료(2026-11-19) — 자동 테스트 + 사용자 실기기 확인 + spec-checker 대조·qa-tester 합격

### F-028: 사진 여러 장 = 한 건 — 받기 부분 (분석은 Phase 005)
- **설명**: 한 번의 공유로 함께 들어온 사진은 원본·사이드카는 장마다 두되 목록 한 줄·항목 보기 한 화면·지우기 한 번으로 다룬다.
  대상 = 같은 `group_id`의 모든 장이 `device`=`phone`·`input`=`share`·`kind`=`image`.
- **수용 기준**(테스트: `record_test`·`collection_list_test`·`share_test`):
  - [x] 사진 3장 묶음 + 단독 2건 → "전체 3건", 묶음 제목 자리는 메모가 있으면 메모·없으면 "사진 3장"
  - [x] 묶음 줄의 자리(시각) = 대표 장 = base가 가장 이른 장
  - [x] 장 순서 = `original_name` 자연 정렬(`p2`·`p10`·`p1` → 1·2·10), 이름 없는 장은 뒤로·그 안은 base 순
  - [x] 대상 아님: png + pdf 묶음 → 2줄 / 기존판 형식 `pc_file` png 2장 묶음 → 2줄 / 옛 묶음(대표가 아닌 장에 결과 파일) → 장마다 한 줄
  - [x] 일부만: `group_size`=3인데 사이드카까지 있는 장이 2 → 한 줄, 빠진 장 1("3장 중 2장")
  - [x] 검색: 2번째 장의 파일 이름에만·메모에만 있는 낱말 → 그 묶음 1건
  - [x] 지우기: 3장 묶음 → 파일 6개 삭제(원본 3·사이드카 3), 대표가 아닌 장 먼저·대표 장의 원본이 맨 마지막, 다른 건 0 /
        중간 실패 → 그 뒤 삭제 0, 대표 장 파일 전부 남고 목록에 묶음이 남는다
  - (사용자 실테스트) 갤러리에서 사진 2장 공유 → 목록 1줄 "사진 2장" → 항목 보기에 2장이 세로로("k / N · 파일 이름 · 눌러서 확대")·확대 → 지우기 확인 창에 "사진 2장"
- **Phase 005로 넘기는 것**: 한 요청으로 분석·대표 장에만 ai 파일·"N장 중 K장으로 분류함"·사본 줄이기·핵심 정리
- **상태**: 받기 완료(2026-11-19) — 자동 테스트 + 사용자 실기기 확인 + spec-checker 대조·qa-tester 합격

### F-018: 목록에서 지우기
- **설명**: 한 건의 폰 파일(`records/YYYY-MM/`에서 이름이 `<base>.`로 시작하는 것 전부)을 바로 지운다. 휴지통이 없어 되돌릴 수 없다.
  지우는 자리 = 목록에서 길게 누름 + 항목 보기의 '삭제', 둘 다 확인 창, 한 번에 한 건.
- **수용 기준**(테스트: `record_delete_test`·`collection_list_test`·`collection_screen_test`):
  - [x] 한 달 폴더에 그 건 파일 5개(원본·meta·ai·user·자막) + 다른 건 파일 2개 → 그 건 5개가 0개, 다른 건 2개 그대로, 순서 = 덧붙임 → 사이드카 → 원본
  - [x] 모르는 꼬리(`<base>.foo.bar`)·쓰다 만 `.tmp`도 지운다 / 이름이 base로 시작만 하고 바로 뒤가 `.`이 아닌 파일은 안 지운다
  - [x] 중간 실패: 3번째에서 실패 → 그 뒤 삭제 0, 원본 남음, 화면 문구 "지우지 못했습니다(5개 중 2개 지움) — 다시 지우세요"
  - [x] 지우는 사이 이미 없어진 파일 → 건너뛰고 나머지를 지움, 로그 1줄
  - [x] 하나도 못 찾으면 지운 수 0 / base가 이름 규칙(`YYYYMMDD-HHMMSS_<8자>`)이 아니면 오류이고 지운 파일 0개
  - [x] 확인 창에서 취소 → 삭제 0건(길게 누름·항목 보기 둘 다) / 지우기 → 그 건 파일 0개·"지웠습니다"·줄이 사라진다
  - [x] 지운 뒤 새로 고쳐도 그 건이 나오지 않는다 / 지우기 전에 시작한 새로 고침이 끝나도 그 건이 되살아나지 않는다
  - [x] 로그에 수집물 본문 0번(base·개수만)
  - (사용자 실테스트) 길게 누름 → 확인 창 문구("폰에서 … 모두 지웁니다 … 되돌릴 수 없습니다") → "지웠습니다" / 항목 보기 '삭제' → 목록으로 돌아오고 줄이 없다
- **Phase 005로 넘기는 것**: 분류가 도는 사이 지운 건에 결과 파일을 쓰지 않는 확인
- **상태**: 완료(2026-11-19) — 자동 테스트 + 사용자 실기기 확인 + spec-checker 대조·qa-tester 합격

### F-029: 목록 자동 갱신
- **설명**: 수집물을 저장한 쪽이 폰 안 신호 파일 `changed.txt`(산출물, 내용 = 시각)를 새로 쓰고, 열려 있는 목록 화면이 3초마다 그 파일만 보고 값이 바뀌었으면 새로 고친다.
  Phase 003에서 신호를 내는 쪽 = 공유 엔진·붙여넣기·녹음. Phase 005에서 분류 작업이 더해진다.
- **수용 기준**(테스트: `change_signal_test`·`share_test`·`paste_screen_test`·`collection_screen_test`):
  - [x] 공유로 1건 이상 저장 → 신호 값 바뀜 / 저장 0건(빈 내용·저장 실패) → 안 바뀜
  - [x] 붙여넣기 저장 1건·녹음 저장 1건 → 각각 신호 값 바뀜 / 실패면 안 바뀜
  - [x] 감시: 기준값과 같으면 "바뀜 아님", 다른 값이 쓰이면 "바뀜" 한 번 / 들어올 때 있던 신호는 기준일 뿐 / 파일 없음 → 아님 / 깨진 파일도 터지지 않는다
  - [x] 두 주체(화면·공유 엔진)가 번갈아 써도 감시는 쓰일 때마다 바뀜을 본다
  - [x] 목록을 열어 둔 동안 신호가 바뀌면 폴더 읽기가 1번 더 일어나고 새 줄이 보인다 / 안 바뀌면 3초 틱마다 폴더 읽기 0번 / 목록 화면을 닫으면 감시가 멈춘다
  - [x] 신호 쓰기가 실패해도 던지지 않는다(로그 1줄)
  - (사용자 실테스트) 목록을 열어 둔 채(팝업 화면·분할 화면으로) 다른 앱에서 공유 → 손대지 않아도 줄이 생긴다
- **상태**: 완료(2026-11-19) — 자동 테스트 + 사용자 실기기 확인 + spec-checker 대조·qa-tester 합격
