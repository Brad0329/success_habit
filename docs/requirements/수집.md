# 요구사항 — 수집 — 붙여넣기 · 공유 · 녹음

> `docs/REQUIREMENTS.md`(목차·목표·비기능·하지 않는 것)에서 나눈 기능 절. 결정·수용 기준의 단일 원본.
> 저장은 모두 F-035(폰 안 저장, REQUIREMENTS.md)를 거친다 — 업로드·임시 보관·재전송이 없다.

### F-003: 붙여넣기
- **설명**: 붙여넣기 화면을 열면 클립보드 글이 입력칸에 채워지고, '보내기' 한 번으로 폰에 저장한다.
  Phase 003 동안은 이 화면이 앱의 첫 화면이다(계획 달력은 Phase 004에서 그 위에 열린다).
- **수용 기준**(테스트: `paste_screen_test`):
  - [x] 클립보드에 글이 있을 때 창이 포커스를 얻으면(앱을 열 때·다른 앱에서 돌아올 때) 입력칸에 그 글이 채워지고 상태 줄 "클립보드에서 채움"
  - [x] '보내기'를 누르면 칸의 내용(고쳤으면 고친 내용)이 수집물 1건으로 저장된다 — `input`=`paste`·`device`=`phone`·`source`=`null`,
        원문 바이트는 칸의 글 그대로(앞뒤 공백을 고치지 않는다)
  - [x] 앞뒤 공백을 뺀 전체가 http(s) 주소 하나면 `kind`=`url`, 그 외(문장 속 링크 포함)는 `text`(`record_test`)
  - [x] 저장에 성공하면 칸이 비고 상태 줄 "저장됨 · HH:MM"
  - [x] 빈 칸(공백뿐 포함)으로 '보내기' → 저장 0건, 상태 줄 "빈 칸은 보내지 않습니다"
  - [x] 저장이 실패하면(쓰기 오류를 일으켜) 상태 줄 "저장하지 못했습니다 — 칸의 내용은 그대로 있습니다", 칸의 글은 그대로, `records/`에 그 건의 파일 0개, 로그 1줄.
        같은 글로 '보내기'를 다시 누르면 새 수집물 1건이 된다(재전송 버튼·보관 건수 없음)
  - [x] 한 번 자동으로 채운 클립보드는 보내든 지우든 앱을 껐다 켜도 다시 자동으로 채우지 않는다 / '클립보드에서 다시 채우기'로는 채운다
        (채운 글의 MD5만 `sent_clip.md5`에 남는다 — 글 자체는 남기지 않는다)
  - [x] 화면에 "보내지 못한 것"·"재전송"·"전송 실패"·"보관 중" 글자가 나오지 않는다
  - [x] 로그에 칸의 글·클립보드 글이 0번 나온다(수집 ID·종류만)
  - (사용자 실테스트) 화면 모양이 기존판과 같다(제목 '채록'·비우기·다시 채우기·⋯·입력칸·상태 줄·마이크·'보내기') / 다크 모드 / 다른 앱에서 복사하고 돌아오면 채워짐
- **엣지케이스**: 클립보드 읽기 실패 → 로그만, 칸은 그대로 / `sent_clip.md5` 읽기·쓰기 실패 → 로그만(다음에 다시 채워 보일 수 있다)
- **상태**: 완료(2026-11-19) — 자동 테스트 + 사용자 실기기 확인 + spec-checker 대조·qa-tester 합격

### F-002: 공유 메뉴로 받기
- **설명**: 다른 앱의 공유 메뉴에서 '채록'을 고르면 받은 것을 화면 없이 폰에 바로 저장하고 알림으로 결과를 알린다.
  저장은 공유 엔진(ShareActivity의 Dart 진입점 `shareMain`)이 직접 한다 — 백그라운드 작업을 거치지 않는다.
- **결정**(2026-11-19 사용자): 한 번의 공유에서 일부 파일만 저장에 실패하면 **이번 공유로 쓴 것을 전부 되돌리고** "저장 실패" 한 번 —
  `group_size`가 사이드카에 이미 정해져 있어 일부만 남으면 묶음이 영영 "N장 중 M장"이다.
- **수용 기준**(테스트: `share_test`):
  - [x] 텍스트만 공유 → 수집물 1건(`.txt`, `input`=`share`, `kind`는 F-003과 같은 판정)
  - [x] 파일 1개 공유 → 수집물 1건, 원본 바이트의 MD5 = 받은 파일의 MD5, `original_name`=받은 이름(못 받으면 `null`),
        `kind`는 `image/*`면 `image`·그 외 `file`, MIME을 못 받으면 `application/octet-stream`
  - [x] 파일 N개 공유 → 수집물 N건, 모두 같은 `group_id`, `group_size`=N(용량 초과로 뺀 파일은 세지 않는다). 1건뿐이면 둘 다 `null`
  - [x] 파일 + 텍스트를 함께 공유 → 수집물은 파일 수만큼이고 텍스트는 각 사이드카 `caption`(공백뿐이면 `null`), 텍스트 수집물은 따로 생기지 않는다
  - [x] `source` = 공유해 온 앱 패키지, 안드로이드가 알려 주지 않으면 `null`
  - [x] 100MB를 넘어 빠진 파일은 저장하지 않고 알림 "용량 초과(상한 100MB)"(이름 나열), 같은 공유의 나머지 파일은 저장한다
        (100MB 판정은 Kotlin `ShareActivity` — 크기를 모르면 복사하며 세다 넘는 순간 중단하고 복사본을 지운다. 경계값 자동 테스트 없음 — 기존판과 같음)
  - [x] 저장이 끝나면 알림 제목 "채록 저장됨", 내용 "N건 저장됨"(N = 이번 공유로 저장한 건수)
  - [x] 받은 것이 없거나 공백뿐인 텍스트 → 저장 0건, 알림 "보낼 내용 없음" / "공유받은 내용이 비어 있습니다"
  - [x] 여러 건 중 하나라도 저장에 실패하면(쓰기 오류를 일으켜) 이번 공유의 파일이 0개, 알림 "저장 실패" / "공유를 받지 못했습니다 — 다시 공유하세요", 로그에 남는다
  - [x] 1건 이상 저장하면 F-029 신호 값이 바뀐다 / 0건(빈 내용·저장 실패)이면 안 바뀐다
  - [x] 알림 권한이 꺼져 있으면 붙여넣기 화면 위에 띠 "알림이 꺼져 있어 공유 결과를 못 봅니다 · 설정"이 보이고, 누르면 앱 알림 설정이 열린다. 권한을 켜고 돌아오면 띠가 사라진다(`paste_screen_test`)
  - [x] 공유받은 파일 이름의 확장자가 영문·숫자 1~10자가 아니면 그 확장자를 파일 이름에 쓰지 않는다(MIME 표 → `bin`, `record_test`) /
        경로 조각이 섞인 이름은 저장하지 않는다(`phone_store_test`) — 비기능 2 '파일 경로 정규화'
  - [x] 로그에 공유받은 글·메모가 0번 나온다(ID·종류·출처 패키지·건수만)
  - (사용자 실테스트) 공유 메뉴에 '채록'이 보이고 누르면 화면 없이 끝난다 / 알림 모양·문구 / 텍스트·링크·갤러리 사진 1장·사진 2장·문서 파일 1개 → 목록에 보임 /
    공유가 끝나면 사본 폴더(`share_inbox/`)가 남지 않는다 / 고장 상태: 알림 권한을 끄고 공유 → 앱을 열면 띠가 보이고 목록에는 저장돼 있다
- **알려진 한계**: 알림 권한이 꺼진 채 공유 저장이 실패하면 로그에만 남는다(띠가 그 위험을 알린다) / 공유 엔진이 중간에 죽으면 사본 폴더(`share_inbox/`)가 남는다(치우는 주체 없음 — 복사 중 예외는 Kotlin이 지운다) /
  한 번의 공유는 파일을 하나씩 읽어 저장한다(전부를 한꺼번에 메모리에 올리지 않는다)
- **상태**: 완료(2026-11-19) — 자동 테스트 + 사용자 실기기 확인 + spec-checker 대조·qa-tester 합격

### F-007: 앱 안 음성 녹음
- **설명**: 붙여넣기 화면의 마이크 버튼으로 녹음하고, '완료 · 저장'·앱 벗어남·60분 상한에서 멈추고 폰에 저장한다. 포그라운드 서비스는 없다.
- **수용 기준**(테스트: `paste_screen_test`):
  - [x] 녹음 → '완료 · 저장' → 수집물 1건: 원본 `.m4a`(`audio/mp4`) + 사이드카, `input`=`voice`·`kind`=`file`·`original_name`=`null`·`device`=`phone`,
        상태 줄 "저장됨 · 녹음 MM:SS · HH:MM"
  - [x] 녹음 중 앱을 벗어나면(`hidden`·`paused`) 그때까지 녹음한 것이 그 자리에서 수집물 1건으로 저장되고, 돌아오면 상태 줄에 보인다.
        알림창 내리기(`inactive`)에서는 멈추지 않는다
  - [x] 60분에 닿으면 자동으로 멈추고 저장한다 — 59분 59초에는 녹음 중, 60분 00초에 저장 1건
  - [x] 1초 미만 녹음은 저장하지 않고 "너무 짧아 저장하지 않음" — 999ms는 0건, 1,000ms는 1건
  - [x] 마이크 권한이 거부돼 있으면 녹음하지 않고 "마이크 권한이 꺼져 있어 녹음할 수 없습니다" + '설정'(앱 정보 화면)
  - [x] 저장하면 임시 녹음 파일(`voice_tmp/`)이 남지 않는다 / 저장이 실패하면 "녹음을 저장하지 못했습니다", `records/`에 그 건 파일 0개, 임시 녹음 파일은 남긴다(유일한 사본)
  - [x] 녹음 파일이 0바이트 → "녹음 파일을 만들지 못했습니다", 저장 0건
  - [x] 화면이 사라질 때 녹음 중이었으면 그때까지의 것이 저장된다
  - [x] 저장하면 F-029 신호 값이 바뀐다(녹음 중 ⋯ 메뉴로 목록을 열어 둔 경우 목록에 저절로 보인다)
  - (사용자 실테스트) 녹음 중 화면(빨간 상자·경과 시간·"녹음 중 · 최대 60:00"·"앱을 벗어나면 여기까지 저장"·'완료 · 저장') / 다크 모드 /
    고장 상태: 녹음 중 홈 버튼 → 돌아오면 저장돼 있고 목록에서 재생된다
- **알려진 한계**: 저장에 실패한 녹음의 임시 파일을 되살리는 기능은 없다
- **상태**: 완료(2026-11-19) — 자동 테스트 + 사용자 실기기 확인 + spec-checker 대조·qa-tester 합격
