### F-017: ⋯ 메뉴
- **설명**: 모든 화면의 앱바 오른쪽 끝 ⋯ 하나로 화면을 옮긴다. 메뉴 순서 = 계획·설정이고, 입구가 없는 항목은 메뉴에 나오지 않는다.
  메뉴로 연 화면은 지금 화면 위에 쌓고, '계획'은 맨 밑 화면이라 위를 걷어내고 내려간다(실제 앱의 조립 기준은 `계획.md` F-016).
- **갈라지며 달라진 것**(2026-11-21): 붙여넣기·목록·대화·외울 문장 항목과 '비우기'(칸·클립보드) 버튼은 M채록으로 갔다 — 이 앱의 메뉴 항목은 둘이다.
- **수용 기준**(테스트: `app_menu_test`):
  - [x] 입구가 다 있으면 메뉴 순서 = 계획·설정 / 입구가 없는 항목은 안 나온다
  - [x] (가짜 화면으로) 계획 → 설정 뒤 뒤로 2번 = 계획·바닥 차례 / 지금 화면 항목은 잠긴다
  - (사용자 실테스트) 계획·설정·설정 편집 화면 모두 앱바 끝에 ⋯ / 메뉴 모양
- **바뀜**(2026-11-26, F-101): 메뉴 항목이 셋 — 계획·설정·도움말.

### F-101: 도움말 — 앱이 지향하는 것(Atomic Habits) + 사용법
- **왜**(2026-11-26 사용자): "메뉴에 도움말을 넣어야 할거 같아.. 이 앱이 지향하는 것은 atomic habits의 정신이라는 것을 밝히고 구체적인 사용방법을 만들어줘"
- **결정**(2026-11-26 사용자): 문구 초안 "이대로 진행" / 맨 끝에 **"이 앱은 Brad 2.0 이 제작했습니다."** + 버전 번호
- **가정**(초안과 함께 보였고 "이대로"): ⋯ 메뉴 세 번째 항목 '도움말' → 위로 쌓이는 스크롤 화면(제목·본문 글, 새 모양 없음) / 처음 켤 때 자동으로 띄우지 않음 /
  버전 = `pubspec.yaml`의 `version`(예: 1.0.0+1 → "버전 1.0.0 (1)") — 새 의존성 없이 코드 상수로 두고 테스트가 pubspec과 대조 / 문구는 코드 안(저장 없음)
